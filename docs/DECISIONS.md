# Decisiones técnicas

| #   | Decisión                                                                           | Motivo                                                                                                                                                                 |
| --- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Next.js 16 (App Router) + TypeScript** para UI y API en un solo proyecto         | Stack recomendado; un único despliegue; Server Components para consultas directas a BD.                                                                                |
| 2   | **Prisma 7.10 (estable)** con `@prisma/adapter-pg`                                 | La etiqueta `latest` de npm apuntaba a una 8.0 RC; se fija la última estable. Prisma 7 exige driver adapter y `prisma.config.ts`.                                      |
| 3   | **PostgreSQL 17** nativo en Windows (+ docker-compose para producción)             | Docker requería WSL2 y reinicio; la instalación nativa permitió probar todo en el momento.                                                                             |
| 4   | **Cola de jobs en PostgreSQL** (`FOR UPDATE SKIP LOCKED`) en lugar de Redis/BullMQ | Sin infraestructura extra; transaccional con los datos; escalable a varios workers.                                                                                    |
| 5   | **Worker in-process** vía `instrumentation.ts` por defecto, con modo `external`    | Un solo proceso para uso personal (`npm run dev`/`npm start`); separable en producción.                                                                                |
| 6   | **OpenStreetMap como segundo proveedor**                                           | Permite usar y probar la app con datos reales sin clave ni coste; demuestra la arquitectura de proveedores. Su menor fiabilidad para "web" se refleja en la confianza. |
| 7   | **Google Text Search con reseñas en la misma llamada**                             | Text Search se factura por llamada (hasta 20 negocios); pedir reseñas ahí es mucho más barato que un Place Details por negocio. Configurable.                          |
| 8   | **Cliente HTTP propio sobre `node:http(s)`** en vez de `fetch` para el crawler     | Permite validar la IP en el `lookup` del socket (anti DNS-rebinding), controlar redirecciones, TLS y tamaño sin dependencias.                                          |
| 9   | **Playwright opcional** (desactivado por defecto)                                  | Solo cuando hace falta (webs 100 % JS); pesado y con riesgo SSRF residual. Sin él, el análisis se marca como parcial.                                                  |
| 10  | **cheerio** para HTML, **libphonenumber-js** para teléfonos                        | Robustez frente a regex frágiles; comparación fiable de teléfonos (E.164).                                                                                             |
| 11  | **Scoring por reglas** (no ML) con desglose                                        | Explicable y configurable, tal y como pide el producto.                                                                                                                |
| 12  | **"Sin web" de OSM → evidencia insuficiente** si no se contrasta                   | En pruebas reales, restaurantes conocidos aparecían "sin web" solo porque OSM no tenía la etiqueta.                                                                    |
| 13  | **Autenticación propia mínima** (scrypt + HMAC) en lugar de un proveedor externo   | Uso de un solo usuario; sin dependencias; obligatoria en producción.                                                                                                   |
| 14  | **PWA + Web Push** en lugar de app nativa                                          | Instalable en Android/iOS sin tiendas, una sola base de código, notificaciones de seguimiento.                                                                         |
| 15  | **CRM ligero** (estado, seguimiento, notas)                                        | Petición del usuario de "organizarse mejor" y estar conectado con los clientes desde el móvil. La app nunca contacta por sí sola.                                      |
| 16  | **CSV con `;` y BOM**                                                              | Excel en español abre correctamente tildes y columnas.                                                                                                                 |
| 17  | Proyecto en `Desktop\Analisis Webs` (ruta corta)                                   | Windows con `LongPathsEnabled=0` y rutas temporales de ~165 caracteres rompían `node_modules`/`.next`.                                                                 |
